# Вход и доступ к данным

Приложение использует логин/пароль, Spring Security и серверную HTTP-сессию. Пароли хранятся как BCrypt-хеши. Самостоятельная регистрация через интернет не включена: аккаунты создаёт оператор скриптом.

## Первый пользователь

В корне проекта экспортируйте настройки нужной БД, затем соберите backend и создайте аккаунт:

```bash
set -a
. ./.env
. ./data/import/vm-database.env
set +a
export DATABASE_URL='jdbc:postgresql://127.0.0.1:15432/finance_support'
mvn -f backend/pom.xml package
./scripts/create-user.sh
```

Для БД на ВМ должен работать SSH-туннель, описанный в `database-setup.md`. Для локальной БД задайте её реквизиты вместо файла ВМ. Скрипт запросит пароль скрыто; используйте согласованный пароль. Пароль не сохраняется в исходниках или аргументах команды. Допустимо от 12 символов до 72 байт UTF-8.

Логин по умолчанию — `vlad13reg`. UUID берётся из `FINANCE_OWNER_ID` (по умолчанию `11111111-1111-1111-1111-111111111111`). Для первого пользователя сохраните UUID, с которым запускался старый backend и импорт: так останутся доступны прежние операции и документы OpenAI. Скрипт применяет Flyway, создаёт аккаунт и завершает процесс без запуска HTTP. Повторный запуск сохраняет пароль; несовпадение UUID существующего логина останавливает выполнение.

Для отдельного пользователя задайте другой UUID явно:

```bash
BOOTSTRAP_LOGIN=another_user BOOTSTRAP_USER_ID="$(uuidgen)" ./scripts/create-user.sh
```

После создания аккаунта запустите backend обычной командой и откройте React UI. Временный запуск через HTTP по IP описан в `deployment.md`; для него требуется `SESSION_COOKIE_SECURE=false`. При включении HTTPS установите `SESSION_COOKIE_SECURE=true`. Перезапуск backend завершает текущие сессии; срок бездействия — 30 минут.

## HTTP-контракт

- `GET /api/auth/csrf` — получить токен и сохранить session cookie.
- `POST /api/auth/login` — форма `application/x-www-form-urlencoded`, поля `username` и `password`, CSRF-заголовок из предыдущего ответа. Возвращает только `id` и `login`.
- После входа снова получить CSRF-токен: при аутентификации он меняется.
- `GET /api/auth/me` — текущий аккаунт; без сессии `401`.
- `POST /api/auth/logout` — завершить сессию, с актуальным CSRF-токеном; ответ `204`.
- Все остальные `/api/**` требуют входа. Изменяющие запросы требуют CSRF. Клиент не задаёт владельца: UUID определяется из сессии.

Лимит входа — 10 попыток за 10 минут с одного IP; затем `429`. Лимит хранится в памяти одного backend. Сервер доверяет proxy-заголовкам только от локального reverse proxy. В production обязательно `SESSION_COOKIE_SECURE=true` и HTTPS; локально — `false` для HTTP. React хранит только состояние входа в памяти, пароль и session token в browser storage не записываются.

## Импорт и операции

RAG-импорт с `--upload` теперь запрашивает пароль приложения; логин задаётся `--login`, по умолчанию `vlad13reg`. Для удалённого API используйте HTTPS или локальный SSH-туннель. Прямой импорт CSV в PostgreSQL по-прежнему использует DB-реквизиты и явно выбранный UUID владельца.

Редактирование меняет сумму, дату, тип, категорию, магазин, описание и способ оплаты. Категорию можно выбрать из подсказок или ввести новую. `DELETE /api/transactions/{id}` помечает запись `deleted_at`; списки и отчёты её исключают. Изменять чужую или удалённую запись нельзя (`404`). Ключи импорта и идемпотентности сохраняются: повторный импорт не восстанавливает удалённые операции. Повтор создания через API с ключом удалённой операции возвращает `409`.
