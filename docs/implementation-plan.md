# План реализации финансового помощника

## Цель

Создать личного финансового помощника: пользователь описывает доходы и расходы обычным текстом, приложение проверяет распознанные операции, сохраняет подтверждённые записи и строит отчёты на основе данных PostgreSQL.

## Архитектура

- **React frontend** отвечает за ввод текста, просмотр распознанных операций, подтверждение/исправление и отображение отчётов.
- **Spring Boot REST API** валидирует запросы и связывает сценарии приложения.
- **Финансовое ядро** хранит транзакции, категории, бюджеты и цели в PostgreSQL. Отчёты рассчитываются SQL-запросами.
- **AI orchestrator** извлекает операции из свободного текста и вызывает ограниченные бизнес-инструменты. Идентификатор пользователя берётся из серверного контекста.
- **MCP Finance Server** предоставляет операции для создания, поиска, исправления транзакций и получения отчётов. Он вызывает те же application services, что и REST API.
- **RAG** хранит и ищет правила, финансовые документы и соответствия магазинов/товаров в OpenAI Vector Stores; embeddings и reranking выполняются OpenAI. Он не используется для фактических финансовых сумм и отчётности.

## Этапы

1. **MVP — финансовое ядро и веб-сценарий.** Поднять React, Spring Boot и PostgreSQL; реализовать разбор ограниченного набора русскоязычных фраз локальными правилами и опциональное извлечение через OpenAI Responses API со строгой JSON Schema. Добавить предварительный просмотр и подтверждение нескольких операций, список/редактирование транзакций, категории и месячный отчёт. Расчёты выполняются в PostgreSQL, деньги представлены как `BigDecimal`/`NUMERIC`.
2. **MCP Finance Server.** Экспортировать `record_transactions`, `search_transactions`, `update_transaction`, `get_financial_report` и `list_categories`. Добавить авторизацию инструментов и идемпотентность входящих сообщений.
3. **AI Orchestrator.** Расширить извлечение до безопасного tool-calling диалога; добавить уточнение неоднозначных операций и разрешённые серверные бизнес-инструменты. Модель не получает произвольный SQL и не объявляет запись успешной до ответа сервера.
4. **RAG — текущая реализация.** Загружать текстовые материалы в OpenAI Vector Stores, отслеживать асинхронную индексацию, искать с фильтром владельца и встроенным reranking. Следующее расширение — применение RAG к классификации транзакций, персональные примеры после подтверждения, форматы файлов и управление индексом.
5. **Расширение продукта.** Бюджеты, финансовые цели, сравнение периодов, аномалии, импорт банковских операций и плановые отчёты.

## Границы MVP

В MVP входят создание нескольких расходов из поддерживаемого текста, подтверждение перед сохранением, просмотр и исправление записей, категории и месячный отчёт по доходам/расходам. Переводы между своими счетами не должны искажать отчёт.

MCP, полноценный tool-calling диалог, парсинг PDF/Office, публичная регистрация и восстановление пароля, бюджеты, банковские интеграции и автоматические отчёты — следующие этапы. OpenAI-разбор и RAG отключены по умолчанию; при включении RAG полные загружаемые документы сохраняются в OpenAI, а запрос и найденные фрагменты используются для генерации ответа. Вход реализован через Spring Security и серверные сессии; аккаунты создаются скриптом. Для публичного размещения применяются HTTPS и конфигурация из `docs/deployment.md`; реальные проверки БД и сервера выполняются перед выпуском.

## Критерии готовности MVP

- Пользователь может разобрать фразу с несколькими расходами и увидеть черновики до записи.
- Подтверждённые записи сохраняются в PostgreSQL и отображаются в списке.
- Операцию можно исправить; отчёт за выбранный месяц обновляется по фактическим данным.
- Суммы, даты, категории и границы месяца обрабатываются предсказуемо; собственные переводы исключены из доходов и расходов.
- Frontend и backend запускаются воспроизводимыми командами из README.

## Следующая версия: персональный финансовый чат

1. Реализованы вход, изоляция владельцев, пользовательские категории в истории, способы оплаты и значение «Карта» для новых операций. Следом добавить полноценное управление категориями и настройку предпочтений.
2. Подготовить импорт справочников и истории Google Sheets только на чтение с предварительной сверкой. Исходную таблицу не изменять.
3. Хранить черновики и версии диалога в PostgreSQL; уточнять неизвестные обязательные поля кнопками до сохранения. Защитить подтверждение от повторной записи.
4. Перед классификацией искать релевантные документы и подтверждённые примеры в OpenAI; сопоставлять результаты с актуальными локальными записями.
5. Сохранять исправления только после подтверждения, обновлять индекс через надёжные фоновые задания, поддержать отмену ошибочных правил.
6. Сделать мобильный чат основным сценарием; добавить загрузку файлов и управление источниками.
7. Проверить качество классификации и развернуть приложение с PostgreSQL на `cave`, с HTTPS, резервными копиями и проверкой восстановления.


## Подготовка к серверному запуску

Реализованы сессии, CSRF, создание первого аккаунта с сохранением UUID прежних данных, форма входа/выхода, редактирование описания и способов оплаты, мягкое удаление с исключением из отчётов. Подготовлены `deploy/`, сборка релиза и установщик с `pg_dump` перед обновлением. Порядок и оставшиеся проверки на настоящем сервере — в `docs/deployment.md`.
