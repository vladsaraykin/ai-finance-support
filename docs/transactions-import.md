# Разовый импорт операций из Google Sheets

Скрипт `scripts/import-transactions-once.py` читает локальный CSV-снимок листа «Операции» и готовит SQL. Запись выполняется напрямую в PostgreSQL, без OpenAI и дополнительных API импорта. Исходная Google-таблица не изменяется.

Нужны Python 3.9+, `psql`, SSH-туннель к БД и актуальная схема. На macOS `psql` устанавливается через `brew install libpq`; при необходимости добавьте `/opt/homebrew/opt/libpq/bin` в PATH.

## 1. Обновить схему

Остановите и заново запустите backend с реквизитами БД на ВМ. Flyway применит `V2__support_history_import.sql`: расширит категории, добавит исходный способ оплаты и метаданные импорта. Backend теперь читает пользовательские категории, не заменяя их на «Другое». Старые операции сохраняются; неизвестные способы оплаты остаются NULL.

Backend нужен для применения миграций и просмотра результата; во время самого импорта он может продолжать работать.

## 2. Предварительный просмотр

Из корня проекта:

```sh
python3 scripts/import-transactions-once.py data/import/google-operations.csv \
  --source-id google-finance-operations
```

Команда проверяет все строки, показывает количество и месячные суммы и сохраняет SQL в `data/import/transactions-import.sql` (права `600`, каталог исключён из Git). Подключения к БД на этом шаге нет. Сверьте суммы и выбранного владельца перед записью.

Полный CSV, скачанный из Google Sheets, и подготовленный снимок с заголовком в первой строке поддерживаются одинаково. Разделители: запятая, точка с запятой или табуляция. Нужны столбцы «Дата», «Тип», «Категория», «Описание», «Сумма, ₽», «Способ оплаты». Строки с отметкой об ошибке в столбце «Проверка» блокируют импорт. Для пустого/неизвестного способа оплаты скрипт также требует исправления снимка — историческое значение не подставляется автоматически.

Дата операции хранится в полдень соответствующего дня в `FINANCE_TIMEZONE` (по умолчанию Europe/Moscow): это техническое представление даты из таблицы, фактическое время покупки неизвестно. Суммы разбираются через Decimal; деньги передаются как точные десятичные значения. Оплата переводом остаётся расходом/доходом своего типа. Тип «Перевод» между собственными счетами не попадает в доходы и расходы отчёта.

## 3. Записать

Туннель на `127.0.0.1:15432` должен работать по [инструкции БД](database-setup.md). В терминале импорта загрузите настройки:

```sh
set -a
. ./.env
. ./data/import/vm-database.env
set +a
export DATABASE_URL='jdbc:postgresql://127.0.0.1:15432/finance_support'

python3 scripts/import-transactions-once.py data/import/google-operations.csv \
  --source-id google-finance-operations --apply
```

Если приложению задан собственный `FINANCE_OWNER_ID`, задайте его и скрипту через окружение или `--owner-id`. Скрипт выводит выбранного владельца. Пароль PostgreSQL передаётся через временный файл pgpass с правами `600`, который удаляется после завершения; пароль не попадает в SQL и аргументы `psql`.

Запись выполняется одной транзакцией. Ответ `inserted` показывает новые операции, `skipped` — ранее импортированные. Две одинаковые покупки в разных строках сохраняются как две операции. Строка идентифицируется владельцем, `source-id` и номером строки исходного листа. Для данного листа первая строка данных — 7; если ваш лист устроен иначе, укажите `--first-data-row`.

При повторе используйте **тот же source-id, тот же порядок и номера строк**. Не сортируйте и не удаляйте строки в снимке между попытками. Если ранее импортированная исходная строка изменилась, весь импорт остановится для сверки. Изменения, сделанные в приложении после импорта, повторным запуском не перезаписываются. Другая строка, добавленная вручную или другим импортом, автоматически дублем не признаётся. Не используйте новую метку source-id для обхода конфликта: это создаст повторные операции.

## 4. Проверить результат

Обновите UI и выберите месяц импортированных операций. Сверьте количество, доход, расход, разницу и категории с предварительным просмотром. Исходное название категории доступно в БД в `import_category`; стандартные категории сопоставляются с кодами приложения, пользовательские сохраняют свои имена. Способ оплаты хранится в `payment_method` и доступен для просмотра и изменения в UI. Для доступа войдите в аккаунт с UUID владельца импорта. Удалённые через UI записи сохраняют метаданные импорта: повтор того же CSV пропустит их и не восстановит.

Загрузка этих операций в финансовую БД не повторяет загрузку документов в RAG и не вызывает OpenAI. SQL-файл и CSV с финансовыми данными остаются только в исключённом из Git каталоге `data/import/`.

Проверки преобразования: `python3 -B -m unittest discover -s scripts/tests -p test_import_transactions_once.py -v`. Проверки чтения пользовательских категорий: `cd backend && mvn test`. Эти проверки не записывают операции в вашу БД.
